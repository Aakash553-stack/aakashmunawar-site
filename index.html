Protocol Pre-Flight

Changing a clinical trial protocol after the trial starts is expensive, and many of those changes are avoidable. Pre-Flight reviews a protocol before the trial begins. It flags missing sections, numbers that contradict each other and heavy patient burden, ties every finding to the page that supports it, and lets a person accept or reject each one.

My contribution

  1. The upload pageWhere a reviewer submits a protocol PDF to start a review.
  2. The PDF review workspaceEach finding is highlighted on the page it cites, so the reviewer can check the evidence in place.
  3. The typed API layerA TypeScript client that connects the frontend to the team's FastAPI backend.

My teammates built the backend, which handles parsing, rule checks and the AI review.

Study Group Matcher

Finding classmates who share your courses and are free at the same times is mostly guesswork. This web app matches Rutgers students into study groups by both.

What I built

  • A Spring Boot REST API with stateless JWT sign-in, BCrypt passwords and group rules enforced on the server
  • A matching algorithm written from scratch: free time is stored as sorted intervals and intersected with a linear two-pointer merge
  • A plain HTML, CSS and JavaScript frontend, with a one-click demo account in an isolated sandbox

ResultMatched an independent brute-force model on 3,000 random schedule pairs and 1,575 ranked recommendations. All 41 JUnit tests pass.

  • Spring Boot

Chicago Crime Explorer

Two years of Chicago police incident data is public, but exploring it means writing SQL. This dashboard makes it filterable in the browser.

What I built

  • A normalized SQLite schema designed from the city's flat CSV, with foreign-key and row-count checks on load
  • A FastAPI backend that reuses the notebook's own queries.sql, adding filters as bound SQL parameters
  • A Chart.js dashboard filtered by date, category, district, community area, arrests and domestic incidents

ResultServes 478,089 incident records (Sept 2024 – Aug 2026). 19 API tests confirm unfiltered results match the notebook exactly.

  • Python
  • SQL
  • SQLite
  • FastAPI
  • pandas
  • Jupyter

Schedule Builder

Five courses with several sections each can add up to over two million possible weekly schedules, far too many to check by hand.

What I built

  • A backtracking search written from scratch that drops a partial schedule at its first time conflict
  • Ranking by fewest days on campus, fewest gaps, latest start or fewest campus switches, over real Fall 2026 Rutgers sections

ResultOn a five-course search it never generates 87% of the 2.26 million combinations and runs 5.9× faster than brute force. 18 tests confirm both find identical schedules.

  • Python
  • Backtracking
  • Standard library only

Campus Route Finder

Rutgers–New Brunswick is spread across campuses on both sides of the Raritan River, so the shortest walk between two buildings isn't always obvious.

What I built

  • Dijkstra's algorithm and a binary-heap priority queue, both implemented from scratch
  • A graph of 24 real OpenStreetMap locations, where cross-river routes go over the Landing Lane Bridge

ResultEvery route matches an independent Floyd–Warshall computation, checked for every pair of locations.

I'm a Computer Science student at Rutgers University–New Brunswick. I started my CS coursework at Raritan Valley Community College before transferring.

I like building complete applications: designing the database, writing the backend API, building the interface, and working out the algorithm in between.
